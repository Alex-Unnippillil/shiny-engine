# LookLock — creator review workflow (0.4.0)

## The use case

A creator wants the appearance of a DLSS-treated game replay or presentation frame without allowing the treatment to repaint a scoreboard, subtitle, annotation, or label. **LookLock takes the original and a matching processed still, copies the original pixels back into user-selected regions, and exports a reviewed composite.** The useful distinction is the end-to-end source-preservation review and reproducible handoff, not a claim that region masks are new.

This is a working companion to a renderer, not another DLL swapper and not an enabled DLSS inference backend. Imported DLSS results are user-described and unverified. The empty model-approval register and all OpenDLSS-NR gates remain unchanged. No NVIDIA binaries, model weights, manager code, caller-validation shims, or remote inference are added.

The built-in **Orbital Run** example is a fictional game scene drawn in Canvas. Its treatment is deliberately edited to change a score and a caption. It is clearly labeled synthetic and is NOT a sample generated by DLSS or any model.

## Use it

1. Open **LookLock** from the extension popup, Media Lab navigation, or `/apps/looklock/index.html` on the local site.
2. Load an original PNG/JPEG/WebP/AVIF. Alternatively, select a local MP4/WebM/Ogg, use its native video controls to choose a moment, and click **Use this frame**. **Save original frame PNG** provides the exact decoded frame to send to your separately installed renderer.
3. Import the matching processed image. Dimensions must match exactly; LookLock does not align, crop, scale, or synchronize external results. Confirm that both images are the same frame and crop before exporting. A dimension match alone is not enough.
4. Draw protected regions with mouse or touch, use the HUD/subtitle shortcuts, or enter integer pixel coordinates. Remove, undo, redo, or clear locks as needed.
5. Compare Original, Treatment, Protected, Split, and Changes views. Select treatment blend and outside-only feather. The change-map threshold controls highlighting, not the output treatment.
6. Export the protected PNG, three-panel review board, mask PNG, recipe, or review report. Source files are never overwritten by the application.

The keyboard can operate all controls. Numeric region fields provide an alternative to drawing. When not editing or focusing a button, keys 1–5 choose the five views. Escape cancels an active import or drawing gesture. Inside the video picker, Escape cancels that picker without replacing the original. **Clear session** releases the current media and locks.

## What the outputs mean

- **Protected PNG:** straight RGBA bytes from the working composite. A small original PNG encoder writes lossless DEFLATE stored blocks, avoiding an extra canvas premultiplication round trip during export. PNGs can be larger than compressed image-editor exports.
- **Mask PNG:** black means preserve source, white means permit treatment, gray is the outer feather. Check mask polarity in the receiving tool. The mask does not include the global blend amount.
- **Review board:** source, raw treatment, and protected result, scaled for review with clear provenance and scope captions. It is not a full-resolution evidence image.
- **Recipe:** versioned JSON containing normalized locks, adjustments, dimensions, and SHA-256 identities of both decoded frame buffers. Reimport the exact pair before loading a recipe. Wrong-pair, malformed, duplicate-ID, oversized, or out-of-range recipes are rejected before changing the composition.
- **Review report:** the recipe, output pixel hash, exact protected mismatch count, raw/output change counts, user-described treatment origin, and limitation statements. No filenames, image payloads, or local paths. This is a local record, NOT a signed attestation, model-provenance verification, or proof of semantic truth.

Pixel identity hashes cover the UTF-8 prefix `looklock-rgba-v1:WIDTH:HEIGHT:` followed by decoded RGBA bytes. They do not identify original compressed file bytes or establish a chain of custody. Browser color conversion/decoding may differ across environments; a recipe safely rejects a different decoded result.

## Composition and bounds

`packages/looklock/core.ts` implements validation, normalized rectangle rasterization, union masks, composition, numerical comparison, recipe validation, and bounded region history. Protected cores use exact source RGBA copies. Feathering extends only outside the core and overlapping regions use maximum source protection. Partially blended pixels use alpha-aware premultiplied interpolation; zero/full endpoints copy bytes directly. Transparent pixels remain subject to the initial browser's decoding/color normalization.

This is a bounded CPU/Canvas2D **still-frame** workflow, independent of GPU/model availability. It is not a real-time neural path. Inputs are at most 4,194,304 pixels and 4096 pixels per axis, 50 MiB per still, and 2 GiB per video. No silent downsampling. At most 24 rectangular locks and 60 undo states; recipes are limited to 32 KiB. Selection is transactional and cancelled/obsolete decoders cannot publish a new source. Video URLs, decoders, and temporary downloads are disposed.

The Changes view uses the maximum absolute RGBA-channel difference at each pixel. A large difference can be an intended color change, not invented content. It cannot detect whether a result is authentic or correct. Protected mismatch checks apply only to selected cores and the decoded working source, not all captions/faces or original metadata. There is no text recognition, automatic segmentation, object tracking, temporal masking, HDR preservation, batch video processing, or automatic invocation of external tools.

Do not substitute a generatively altered frame for unmodified scientific, medical, legal, or other evidentiary material. Keep the original; this workspace is for creative review.

## Reference assessment

The user supplied community managers and players as inspiration. The design uses their public descriptions to identify an adjacent creator workflow, not to copy code or binaries:

- `Zonnery/dlss5-nr-player` describes live/offline video processing and separately supplied NVIDIA dependencies. LookLock accepts an exported still; it does not invoke its NGX path or caller shim.
- `Merserk/dlss5-visual-enhancer` already describes composition masks and output comparison. Its LICENSE is source-available proprietary, not generally reusable open source. No source or binary from that project is copied. Importing an image does not establish the sender's rights or processing provenance.
- The supplied Shiny Engine research plan requires exact model/backend labeling, region protection, local processing, and independently established model rights. LookLock leaves the gated inference architecture intact.

Reference URLs: https://github.com/Zonnery/dlss5-nr-player and https://github.com/Merserk/dlss5-visual-enhancer (README and LICENSE reviewed for this iteration). This assessment does not certify those applications' performance, hardware coverage, licensing of third-party assets, or security.

## Verification

`npm run check` includes deterministic tests for zone bounds, feathering, overlap, alpha, byte-preserving endpoints, mismatch metrics, hash binding, hostile recipes, history, independently decoded PNG CRC/Adler correctness, multi-block images, and randomized source locks.

`npm run test:browser` also runs `tests/browser/looklock.py`: actual UI, mouse/touch/keyboard paths, exports, frame-pair confirmation, source/recipe rejection, load races, cancellation, local WebM decoding/frame freeze, responsive widths, and an installed MV3 extension. All existing spatial, neural-gate and Windows compile/protocol/HLSL checks remain required before merge. Review the exact commit's CI results. No trained-model inference or physical-GPU performance claim is derived from these tests.
